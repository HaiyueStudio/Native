# iPhone 关卡进出性能

设备：iPhone 15 Plus，iOS 18.7.3；Metal，1864×860，4× MSAA，pixelRatio 2。

每组从相同章节位置进入关卡、退出，重复两次。保留 820 ms 的原有缩放动画。统计中的最长停顿是最大帧间隔，包含第一帧之前的同步操作，完整转场耗时则包含动画。优化后的第一轮测量额外记录原生 GPU 调用耗时；正常游戏不开启探针。

主要修改：

- 原来每格地砖单独创建实体，父场景和子场景预览进一步放大了对象数。现在按棋盘格两色合并，每间房地面两个实体，仍为每格两个三角形，保留原高度和洞口。
- 进入独立关卡只克隆该关的箱子；原逻辑会复制整个世界的房间定义。保留导入、导出箱子和完成记录的原有规则。
- Intro / Reference / Flip 章节对象数由 3180 / 3274 / 3072 降为 849 / 904 / 860。完整父场景继续保留。
- 批量替换、缩放场景时，共享空间索引的更新成本高于直接裁剪。通过引擎公开的 `spatialCullingThreshold` 配置跳过空间索引前置筛选，继续使用逐物体视锥裁剪，不修改引擎。

第一轮真机对照：最长停顿从 1.2–3.3 秒降至 0.2–0.36 秒，转场可呈现帧数从 2 帧增至 32–42 帧。仍有短暂的首帧停顿，不能称为完全无卡顿。

最终版 `culling.jsonl` 完成五章共 20 次进出，未包装原生 GPU 方法。Intro / Reference / Flip 最长停顿为 97–148 ms，Clone 为 179–207 ms，Transfer 为 164–294 ms。完整转场约 0.9–1.03 秒，包含原有 820 ms 动画。前三章每次转场实际呈现 34–49 帧，较大的两章为 27–30 帧。

诊断直接加载整个章节的数据准备仍需约 0.69–1.20 秒；这种夹具加载会替换全部房间定义，不能等同于普通的小关卡进出。没有宣称所有首次加载或所有关卡都已达到稳定 60 FPS。

原生 15 项单测、地面与章节 19 项检查、墙体与镜像 15 项检查通过。浏览器镜像 82 项、递归转场 47 项通过，地砖截图已审阅。仅做 Boxbound 定向构建与检查，未修改引擎。

最终 iPhone 26 项功能检查全部通过，包括全屏与安全区、Engine 触控入口、MSAA 切换、完成返回与自动存档、镜像方向及撤销、音效、静止停止渲染。已审阅 `iphone.png` 并恢复正常启动，`normal.jsonl` 确认 `smoke:false`。测试使用隔离存档，没有覆盖玩家原有存档。

重复到达同一场景后，对象、几何体、材质及 GPU buffer 数回到相同水平。本次不是长时间泄漏或热稳定性压力测试。

原始记录为 `baseline.jsonl`、`floor.jsonl`，最终结果为 `culling.jsonl`，统计为 `validation.json`。`final.jsonl` 是合并地面后、调整裁剪前的五章对照。`final-backgrounded.jsonl` 是启动后立即切入后台的无效样本，没有纳入计时。

复现：`node scripts/device-ios.mjs <device> launch transitions`，结束后复制 journal，再用普通 `launch` 恢复正常存档。
